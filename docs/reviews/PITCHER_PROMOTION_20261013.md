# 투수 후보 운영 승격 검토

판정일: 2026-10-13 (Asia/Seoul). **승격하지 않음.** 운영 모델, 확률 정책, 스냅샷 feature gate는 유지했습니다.

## 비교 기준을 바로잡은 결과

이전의 53.2%는 새로 학습한 피처 축소 기준 모델의 점수였습니다. 실제 운영 아티팩트의 점수가 아니었습니다. 같은 후보와 같은 최종 검증 경기를 고정하고, 승인 아티팩트 `2026-08-23-befe94ab5baf5496`를 과거 경기일 기준으로 재현했습니다.

| 2026-09-04~2026-10-11, 124경기 | 승인 모델 | 투수 후보 |
| --- | --- | --- |
| 적중 경기 | 78 | 80 |
| Accuracy | 62.90% | 64.52% |
| Brier Score | 0.2412 | 0.2331 |
| Log Loss | 0.6754 | 0.6592 |
| 55% 이상 구간 적중률 | 65.79% (38경기) | 67.61% (71경기) |

두 모델의 확신 구간은 서로 다른 경기 집합입니다. 전체 동일 경기의 paired bootstrap은 날짜 단위로 수행했으며 정확도 차이 +1.61%p의 95% CI는 **-8.20~+11.57%p**였습니다. 개선 신호는 있으나 통계적으로 안정적인 승격 근거는 아닙니다.

## 선발 정보 시점 감사

공식 경기 ID·팀으로 스냅샷과 일정을 연결하고, 경기 전 기록된 마지막 예측 실행 시각을 기준으로 다음 조건을 적용했습니다.

```text
snapshot_time <= prediction_reference_datetime < scheduled_start_datetime
```

추정 선발은 확정 선발로 인정하지 않습니다. 조건을 충족하는 마지막 스냅샷의 선발 이름과 실제 등판 선발을 비교했습니다.

- 선발 248건 중 222건 확인, 26건 미검증
- 양 팀 모두 확인된 경기: 111경기
- 13경기(9월 23~27일)는 보관된 공식 일정 시작 시각 레코드가 없음
- 검증된 111경기에서는 두 모델 모두 72경기 적중, **64.86%**
- 미검증 13경기를 임의 시각이나 추정 일정으로 통과시키지 않음

현재 저장된 원천으로 재현한 값이지, 당시 그대로 보관된 운영 확률 로그라는 의미는 아닙니다. 학습 구간의 선발 출처와 기존 기본 피처도 별도 누수 감사를 완료해야 합니다.

이번 비교 대상은 승인된 **승패 분류 모델**입니다. 대시보드의 최종 `hybrid_50_50` 정책 전체에 대한 비교는 아니며, 후보를 적용한 최종 정책도 별도의 shadow 검증이 필요합니다.

## 승격 차단 사유

1. 실제 승인 모델 대비 bootstrap 신뢰구간이 0을 포함합니다.
2. 모든 최종 검증 경기의 선발 as-of 증명이 완료되지 않았습니다.
3. 후보는 경기 단위 투수 피처를 사용하지만 현재 승인 모델은 팀 단위 추론 계약입니다. 단순 바이너리 교체로 동일하게 서빙할 수 없습니다.

`safe_to_replace_model=false`, `safe_to_use_pitching_snapshot_as_features=false`를 유지합니다. 승격 게이트를 낮추거나 스냅샷을 운영 학습 피처로 연결하지 않았습니다.

대형 원천 복사본과 모델 바이너리는 Git에 포함하지 않습니다. 감사 JSON에 입력 파일의 SHA-256을 남깁니다. 동일 결과 재현에는 해당 입력 버전과 신뢰할 수 있는 승인 아티팩트가 필요합니다.

```bash
cd kbo_analytics
.venv/bin/python -m modeling.pitcher_promotion_review \
  --source-dir "$PWD" \
  --artifact-root "$PWD/modeling/artifacts" \
  --candidate-audit ../docs/reviews/pitcher_candidate_selection.json \
  --output-dir /tmp/kbo-promotion-review-new
```

출력 경로는 새 디렉터리여야 합니다. 이 명령은 모델을 승격하거나 운영 결과를 덮어쓰지 않습니다. 운영 자동화와 동시에 실행할 때는 동일한 `/tmp/kbo_pipeline_update.lock`을 사용합니다.
